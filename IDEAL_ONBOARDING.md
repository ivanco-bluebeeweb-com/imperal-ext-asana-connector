# Asana Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: проектный
менеджер/тимлид, использующий Asana.

## 1. Credential type
Personal Access Token (API key, одно поле).

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` со ссылкой "My Settings > Apps > Manage Developer
   Apps > Personal Access Tokens".
2. **Форма** — token (password-type), с честным описанием "виден только тот набор
   workspace/проектов, к которым у вас есть доступ как у пользователя, создавшего
   токен" — важно, т.к. это НЕ scope-ограниченный OAuth, а полный доступ владельца.
3. **После успеха** — `check_access` (честный отчёт по видимым workspace/проектам) +
   сразу возможность вызвать `list_tasks` по любому проекту — это уже описано в
   POST_CONNECT_EXPERIENCE, идеальный флоу здесь: сделать этот выбор проекта явным
   элементом ПЕРВОГО экрана (не отдельным шагом после), т.к. без выбора проекта список
   задач невозможен.
4. **Multi-workspace** — если токен видит несколько workspace — селектор рабочей
   области ДО выбора проекта (двухуровневая иерархия), с автообновлением списка
   проектов при смене workspace.
5. **Ошибка "expired token"** — Asana PAT не истекает по времени сама, но может быть
   отозвана — конкретное сообщение "токен был отозван в Asana", не "истёк".
